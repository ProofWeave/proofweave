# OpenAI GPT-5 Responses API Migration Notes (raw snapshot 2026-05-08)

> Raw evidence pack. Combines the public Responses API reference, the DevDay 2026 keynote transcript excerpts that touched on the API surface, and the breaking-change log from the OpenAI changelog blog between 2026-03-15 and 2026-05-08.

## 1. What changed at the surface

The legacy `POST /v1/chat/completions` endpoint is now in maintenance mode. New
features ship only on `POST /v1/responses`. The two endpoints share an account
quota but are billed separately and have different rate limit buckets.

`POST /v1/responses` accepts `input`, which can be:

- a plain string,
- an array of `{type: "input_text" | "input_image" | "input_file", ...}` items,
- or a typed `Response.Input` array generated by the SDK helpers.

The `model` parameter must be one of:

- `gpt-5`
- `gpt-5-mini`
- `gpt-5-nano`
- `gpt-5-reasoning`
- legacy aliases `gpt-4.1`, `gpt-4.1-mini`, `gpt-4o`, `gpt-4o-mini` continue to
  work but are routed to the Responses runtime and may exhibit different
  latency.

The `temperature` parameter still exists but is silently clamped to `[0, 1]`
for `gpt-5-reasoning`. The new field `reasoning.effort` accepts
`"minimal" | "low" | "medium" | "high"` and only applies to the reasoning
models.

## 2. Removed and renamed parameters

| Old (Chat Completions) | New (Responses) | Notes |
|---|---|---|
| `messages` | `input` | shape differs, see SDK helper |
| `functions` | removed | replaced by `tools` with `type: "function"` |
| `function_call` | removed | replaced by `tool_choice` |
| `max_tokens` | `max_output_tokens` | also caps reasoning tokens |
| `logprobs` | `logprobs` | now an object with `top_logprobs` field |
| `stream_options` | `stream` + `include` | partial deltas are typed |

The `n` parameter is removed. To get multiple candidates, call the endpoint
multiple times or use `parallel_tool_calls`.

## 3. Tool calling

Tool calls now arrive as typed `response.output` items:

```json
{
  "type": "function_call",
  "id": "call_abc",
  "name": "lookup_invoice",
  "arguments": "{\"invoice_id\": \"inv_001\"}"
}
```

You reply by appending a `function_call_output` item to the next request:

```json
{
  "type": "function_call_output",
  "call_id": "call_abc",
  "output": "{\"status\": \"paid\"}"
}
```

The previous pattern of stuffing tool replies into a `role: "tool"` message is
deprecated and will return HTTP 410 after 2026-09-01.

## 4. MCP and OAuth/DPoP

`tools` now supports `type: "mcp"` for Model Context Protocol servers. The
server URL is provided via `server_url`. If the MCP server requires
authentication, the supported flows are:

1. Bearer token via `headers.Authorization`.
2. OAuth 2.1 PKCE handshake brokered by the platform UI, where the resulting
   short-lived token is injected by the runtime.
3. DPoP-bound tokens with the `dpop` proof attached as `headers.DPoP`. The
   runtime validates the `htu` claim against `server_url` and rejects proofs
   older than 60 seconds.

The MCP tool result lands in `response.output` as
`{"type": "mcp_call", "server_label": "...", "name": "...", "output": "..."}`.

## 5. Streaming

`stream: true` now emits typed Server-Sent Events. The most relevant types:

- `response.output_text.delta` — incremental output text.
- `response.function_call.delta` — incremental tool call arguments.
- `response.completed` — final usage and stop reason.
- `response.error` — terminal error event with `code` and `message`.

The legacy `data: [DONE]` sentinel is still emitted at the end of the stream
for backward compatibility.

## 6. Working code

```ts
import OpenAI from "openai";

const client = new OpenAI();

const res = await client.responses.create({
  model: "gpt-5-mini",
  input: [
    { role: "user", content: "Summarize the attached invoice." }
  ],
  tools: [
    {
      type: "function",
      function: {
        name: "lookup_invoice",
        parameters: {
          type: "object",
          properties: { invoice_id: { type: "string" } },
          required: ["invoice_id"]
        }
      }
    }
  ],
  tool_choice: "auto",
  max_output_tokens: 800,
  reasoning: { effort: "minimal" }
});

for (const item of res.output) {
  if (item.type === "output_text") {
    console.log(item.text);
  }
}
```

## 7. Breaking-change cutover dates

- 2026-06-01: `functions` and `function_call` parameters return HTTP 400 on
  `/v1/responses`.
- 2026-09-01: legacy `role: "tool"` messages return HTTP 410 on
  `/v1/responses`.
- 2026-12-01: `/v1/chat/completions` enters read-only mode (existing
  conversations work, new ones rejected).

## 8. Common migration pitfalls

- Forgetting to rename `max_tokens` to `max_output_tokens` causes silent
  truncation because the field is ignored, not rejected.
- Sending `temperature: 1.5` to `gpt-5-reasoning` no longer raises; it is
  clamped and the response includes a `warnings` array.
- The streaming format change means existing SSE parsers that key on
  `choices[0].delta.content` see undefined; switch to
  `response.output_text.delta`.
- DPoP proofs must be regenerated per request; reusing a proof yields HTTP
  401 with `code: "dpop_replay"`.
